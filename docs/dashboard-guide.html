01

The one primitive: transcript parsing

collectUsage() · server.mjs:428

Understand this and the rest follows. Claude Code writes a JSONL transcript for every session under ~/.claude/projects/. The dashboard walks those files line by line and extracts four things. Every KPI, chart, and rate downstream is an aggregation over these.

extract 01

Token usage

Lines containing "usage" → input_tokens, output_tokens, cache create/read, tagged by model & project. Skips <synthetic>.

extract 02

Tool calls

Each tool_use block increments a per-tool counter — the basis for tool-frequency charts and the flow graph.

extract 03

Code churn

structuredPatch lines from Edit diffs → counts of + / − lines added and deleted.

extract 04

Timestamps

First/last activity per session and per day — drives blocks, streaks, heatmaps, and active-now detection.

Each parser caches per file by mtime + size (usageCache, scanCache, failCache), so repeat scans of the ~360 MB transcript corpus are instant after first load.

02

How the chats are taken

two pipelines, one file format

"Taking the chats" happens two ways. The dashboard never calls the Anthropic API directly — for live chat it drives the local claude binary and streams its output; for history and all analytics it reads the JSONL the CLI already wrote.

Live Driving the CLI

POST /api/chat spawns the real claude binary as a subprocess and pipes it:

claude -p \ --input-format stream-json \ --output-format stream-json \ --verbose \ [--resume <id>] [--model <m>]
  • Child stdout is parsed as stream-json events, broadcast to the browser over SSE.
  • User messages are pushed to child stdin as stream-json (text + base64 images).
  • session_id captured from the system/init event. Chats held in an in-memory Map.

server.mjs:630 · POST /api/chat

Reading history

Past conversations are replayed straight from disk — the CLI is the one that authored them.

  • Session list reads the first 64 KB of each .jsonl to derive a title from the opening prompt.
  • Replay reads ~/.claude/projects/<cwd>/<sessionId>.jsonl to reconstruct past turns.
  • Project → folder mapping: the cwd path with [\/:._] collapsed to - (the mangle rule).

server.mjs:616 · historyEvents() / :737 sessions

All analytics ingest chats the same way as history — direct JSONL parsing. No LLM re-processing of chats for metrics; the numbers are counted, not inferred.

03

The cost model

entryCost · PRICE_PER_M · server.mjs:476

Dollars are an Estimate — the dashboard has no billing feed. It applies Anthropic-shaped per-token rates by model family and weights the token classes. Every "$" on the dashboard flows from these two lines.

Rate per million input tokens

Chosen by model family from the model string. Output and cache tokens are scaled off this base.

opus|fable → $15 haiku → $0.80 else → $3 /* sonnet */ server.mjs:476 · PRICE_PER_M(m)

Cost of one usage entry $

Output billed at 5× input, cache-writes at 1.25×, cache-reads at 0.1× — then divided down from per-million.

cost = ( in·P + out·P·5 + cacheCreate·P·1.25 + cacheRead·P·0.1 ) / 1e6 server.mjs:1600 · entryCost(e)

Estimated cache savings Estimate

Cache reads cost ~10% of a fresh input token, so ~90% of what those tokens would have cost is reported as saved.

saved = Σ (cacheRead / 1e6) · PRICE_PER_M(model) · 0.9 server.mjs:522 · /api/usage

Overview & usage KPIs

/api/usage · server.mjs:478

The landing tiles. All are aggregations over collectUsage() entries.

Active 5-hour block

Mirrors Claude Code's 5-hour billing window. A block starts hour-floored at first activity; a new one opens on the first activity after the prior block ends. Tokens/messages in the current block are summed and split per model.

Daily series & heatmap

126 days of activity grouped by ISO date — output tokens, messages, tool calls, and lines changed — feeding the calendar heatmap and sparkline.

Streak

Consecutive days back from today with any activity. An idle today does not break the streak.

Sessions (30d), lines ±(7d), tool calls

Session count = non-agent transcript files modified in the last 30 days. Line churn and tool-call totals are windowed sums from the same entries.

Skill / command / agent quality score

A static heuristic (0–100) rewarding a description, trigger phrases, argument hints, allowed-tools, headings, and code blocks — penalized −10 if the body exceeds 4000 words. Bucketed into perfect / excellent / good / poor.

05

Chat insights

/api/chatstats · server.mjs:2037

Behavioral rates over a rolling window (default 30 days), built from extracted user prompts and per-session tool activity. These describe how you prompt, not just how much.

Correction / reprompt rate

Fraction of prompts that re-phrase the previous prompt in the same session within 3 minutes — measured by token-set overlap. A proxy for "had to try again."

reprompt if sameSession && Δt < 3min && jaccard(prev,cur) ≥ 0.5 rate = reprompts / totalPromptsserver.mjs:2049

One-shot rate

Sessions resolved in a single user message that still did real work (≥1 tool call). High is good.

userMsgs === 1 && toolCalls > 0server.mjs:2056

Abandon rate

Single-message sessions where nothing happened — one prompt, zero tool calls.

userMsgs === 1 && toolCalls === 0server.mjs:2058

Reuse rate & duplicate prompts

Share of prompts that appear more than once (normalized text). The Duplicates view clusters near-identical prompts greedily by Jaccard similarity — slider 0.3–1.0, default 0.75, ignoring slash-commands and prompts under 25 chars.

jaccard(A,B) = |A∩B| / |A∪B| /* token sets */ reuse = dupPrompts / totalPromptsserver.mjs:2008 · /api/dupes :2009

Flow graph

/api/flow · server.mjs:1928

How skills, commands, agents, and MCP servers reference and actually invoke each other — two edge types laid over one graph.

Defined edges

Static: an item's body text mentions another item's name (word-boundary regex) or an mcp__<name> handle.

server.mjs:1957

Observed edges

Dynamic: real Skill/Task/Agent/mcp__* invocations from transcripts, weighted by frequency. Source attributed to the last Skill invoked since the user's prompt.

server.mjs:1967

Derived: dead ends = defined but never observed · cycles = DFS over defined edges · most-traveled path = greedy walk over observed counts.

Task board analytics

/api/board/analytics · server.mjs:3276

The agentic kanban board is the one place with its own stored state (taskboard.json), but its analytics are still computed live from each ticket's stage history.

Percentiles of releasedAt − createdAt across tickets — the honest "how long does a ticket take."

Throughput, bug ratio & time-in-stage

Where it all lives

no database · localhost only

Everything is the local filesystem under $HOME. Writes hit real config files — each destructive write drops a timestamped backup first, and paths outside the allowed roots are refused.

StorePathRole
Session transcripts~/.claude/projects/**/*.jsonlPrimary source for all usage, cost, insights, flow & failure metrics
Global config~/.claude.jsonProjects list, MCP servers
Settings~/.claude/settings.json + projectHooks, enabled plugins, env flags
Capabilities~/.claude/{skills,commands,agents,templates}CRUD targets
Dashboard state~/.claude/taskboard.json, bugs.json, team-designs.json…Board, bugs, teams, evals — versioned on write
Backups~/.claude/dashboard-backups/<ISO>__<path>Timestamped copy before any destructive write

Security boundary — safe() refuses any path outside [ ~/.claude, <project>/.claude, ~/.claude.json ]. The server binds to localhost only. Heavy GET responses are cached (digest 5 min, board analytics 2 min).
